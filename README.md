# AI 推歌 · Code 节点执行逻辑

一个可直接发布到 GitHub Pages 的**纯静态、无需构建**交互页面，使用 `index.html` 即可运行。

## 页面内容

- **最近播放排除**：最近播放 100 首建立 `song_id`、规范化歌名排除集合，候选命中即排除。
- **异常补位**：有效歌曲不足 12 首时，从随机打乱的百万收藏池补位，使用代码校验去重、近期播放和内容规则；候选用尽时返回实际数量。
- **来源连续性控制**：每日推荐与红心雷达均归为偏好来源，同类来源连续达到第 5 首时尝试引入其他来源；无替补时部分超限情况可能保留。

界面使用深海蓝 `#202D57`、淡紫 `#EAE6FB`、青柠色 `#E7F88A`，桌面紧凑布局，手机响应式适配。可点击 Tab，也可在聚焦 Tab 时用左右方向键、Home、End 切换。

**注意：**这是解释产品流程的可交互可视化，并不调用真实 QQ 音乐 API。示意歌曲和 ID 不是实际歌曲数据。

## 本地预览

直接用浏览器打开 `index.html` 即可。也可以在当前目录启动本地服务：

```bash
python3 -m http.server 8000
```

然后打开 `http://localhost:8000/`。

## 部署到 GitHub Pages

### 新建独立仓库

1. 把 `index.html`、`.nojekyll`、`.github/workflows/deploy-pages.yml` 上传到仓库根目录，并提交到默认分支（通常是 `main`）。
2. 打开仓库 **Settings → Pages → Build and deployment**，将 **Source** 设为 **GitHub Actions**。
3. 工作流运行完成后，访问 `https://<用户名>.github.io/<仓库名>/`。

如果仓库名恰好是 `<用户名>.github.io`，则访问 `https://<用户名>.github.io/`。

### 集成到已有 GitHub Pages 站点

- 不要替换现有首页或已有构建配置。
- 把本项目的 `index.html` 放在现有站点的 `song-logic/index.html`（或与现有站点匹配的静态资源目录）。
- 确保现有 Pages 部署流程会发布这个子目录，即可使用 `/song-logic/` 访问。
- **不要直接添加这个包里的独立部署工作流**，除非确认仓库没有其他 Pages 工作流并希望改成根目录部署。

## 文件说明

- `index.html`：完整交互界面，HTML + CSS + JavaScript，无外部依赖。
- `.github/workflows/deploy-pages.yml`：新建独立仓库时可直接使用的 Pages 部署工作流。
- `.nojekyll`：避免 Jekyll 处理静态资源。

## 页面验收

- 3 个标签可以点击切换，页面文字、流程、示例和图例同步更新。
- 桌面宽屏采用紧凑纵向间距，文字不与流程卡片或其他模块重叠。
- 手机按宽度自适应，无横向滚动。
- 深蓝卡片为白字，浅紫和青柠卡片为深蓝字。
- 没有顶部来源数据卡片，也没有底部总结条。
